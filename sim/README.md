# 모의 지원 시뮬레이터 — 경쟁률 예측 · 수험생 모의 지원

가상 수험생 30만 명이 각자의 성적으로 가·나·다군에 원서를 쓰는 상황을 만든다.
학과별 경쟁률은 2026학년도 실제 경쟁률을 일부 반영해 학습한다.
그 시장에서 합격·추가합격을 돌려 **예상 경쟁률**과 **모의 합격 확률**을 낸다.

**앱(`src/`, `dist/`)은 건드리지 않는다.** 결과는 `sim/out/`에만 남는다(git 제외).

## 학습 → 평가 → 모의 지원

```bash
# 1) 학습: 시뮬레이션을 반복해 2026 입시 결과(경쟁률·70% 컷·추가합격)에 수렴시킨다 — 1회 약 1분
npm run train                                # = node sim/converge.js (기본 12회)
node sim/converge.js --iters 15 --eta 0.6 --seed 1 --alpha 0.7 --minGap -3 --holdout 0.2
#    → sim/out/adjust.json (학과별 지원층 보정 δ, 다군 선호 π, 회차별 수렴 기록, 학습 설정)

# 2) 평가: 학습 결과를 적용해 30만 명 × 3회 → 검증 학과 성적과 model.json — 약 2분
npm run sim                                  # adjust.json이 있으면 자동 적용, 학습 때 설정(seed 등)을 그대로 따른다
node sim/run.js --no-adjust                  # 보정 없이 (비교용)

# 3) 모의 지원
node sim/apply.js --kor 95 --math 96 --tam 96,94 --eng 2 --pick "서강대 컴퓨터"
```

**무엇을 보고 판단하나** — `sim/out/report.md`
- 「경쟁률 예측」의 **검증 학과** 행: 학습에서 뺀 학과(기본 20%)의 경쟁률 오차. 학습 학과 행은 예측력이 아니다.
- 「학과별 70% 컷 차이」의 **검증 학과** 행: 자기 합격선을 보지 않은 학과의 70% 컷 차이(0에 가까울수록 좋다).
- 「현실성 점검 — 군별」: 군별 경쟁률·추가합격. 추가합격은 전체·다군만 맞추고 가·나군은 맞추지 않는다.
- `adjust.json`의 `history`: 회차별로 지표가 어떻게 수렴했는지.

**주의**: 학습(`converge.js`)과 평가(`run.js`)는 `seed`로 학습/검증 학과를 나눈다. 평가는 `adjust.json`에 기록된
학습 설정을 따르므로 분할이 어긋나지 않는다. 검증 학과를 바꿔 보려면 `--seed`를 바꿔 **학습부터 다시** 돌린다.

## 그 밖의 실행 예

```bash
node sim/run.js --runs 1 --alpha 0.5 --minGap -2.5

# 수험생 모의 지원 (model.json 필요)
node sim/apply.js --kor 95 --math 96 --tam 96,94 --eng 2 --track 자연 \
  --pick "서강대 컴퓨터" --pick "중앙대 소프트웨어" --pick "한양대 기계"
node sim/apply.js --kor 88 --math 85 --tam 90,86 --eng 3 --track 인문   # 원서 생략 → 군별 상향·적정·안정 추천
```

## 흐름

| 단계 | 내용 | 코드 |
|---|---|---|
| 1. 성적표 | 공통 능력으로 상관된 국·수·탐 백분위(정의상 균등), 영어 등급, 인문/자연 | `makePopulation` |
| 2. 격차 | 1,535개 학과마다 앱 엔진(`src/engine.js`)으로 격차 계산. 수험생별 대응표 보정까지 동일 | `candidates` |
| 3. 지원 규칙 | **격차 < `minGap`(−3%p)인 학과에는 원서를 쓰지 않는다.** 원서 3장의 목표 격차(안정 +1.5 · 적정 +0.3 · 상향 −1.2)를 군에 배정하고, 목표에 가깝고 인기도가 높은 학과를 고른다. 35개 대학 밖('모형 밖 대학')을 택할 수도 있다 | `chooseApplications` |
| 4. 경쟁률 예측 | `log(2026 경쟁률)`을 학과 특성(대학·군·계열·모집인원·합격선)과 시뮬레이션 구조 경쟁률로 설명하는 릿지 회귀를 학습 학과에 적합한다 | `calibrate` |
| 5. 2026 일부 반영 | 학습 학과의 목표 = 실제^0.7 × 예측^0.3. 검증·미공개 학과의 목표 = 예측 | `calibrate` |
| 6. 시뮬레이션 학습 | 학과 인기도 θ를 맞춰 30만 명의 원서 합이 목표 경쟁률을 재현하게 한다 | `fitTheta` |
| 7. 합격·추가합격 | 학과는 환산총점 순으로 뽑는다. 학생은 욕심낸 원서(상향 > 적정 > 안정) 순으로 등록한다. 모형 밖 대학 원서가 합격하면 그보다 덜 욕심낸 원서를 포기하고, 그 자리는 추가합격으로 넘어간다. 학생 제안 지연수락 방식 | `deferredAcceptance` |
| 8. 출력 | 학과별 예상 경쟁률, 회차별 최종 합격선(→ `apply.js`), 격차별 합격확률 곡선 | `run.js` |

## 현재 결과 (기본 가정, 30만 명 × 3회)

### 경쟁률 예측 — 검증 학과(학습에서 뺀 315개)

| | 오차 중앙값 | 실제의 ±30% 이내 | 상관(로그) |
|---|---:|---:|---:|
| **시뮬레이션 예측** | **17.8%** | **73.0%** | 0.74 |
| 경쟁률 예측 회귀값 | 16.0% | 73.7% | 0.75 |
| 2026 정보 없는 시뮬레이션 (기준선) | 42.7% | 40.6% | 0.31 |

검증 학과는 자기 경쟁률을 보지 않고 예측했다. 35개 대학 전체 원서는 17.6만 장으로 실제 17.2만 장과 거의 같다.
군별 경쟁률도 맞는다(예측/실제): 가 4.74/4.79, 나 4.72/4.75, 다 9.26/9.43.

### 현실성 점검 (학습에 쓰지 않은 지표)

| 군 | 추가합격 예측 | 추가합격 실제 | 70% 컷 차이 (환산 %p) |
|---|---:|---:|---:|
| 가 | 85.7% | 62.9% | +0.92 |
| 나 | 85.4% | 68.9% | +0.91 |
| 다 | 105.0% | 217.5% | +1.46 |

- **70% 컷 차이가 +0.98%p다.** 시뮬레이션 등록자가 실제보다 강하다.
  → `apply.js`의 모의 합격 확률은 **보수적(낮게)** 나올 가능성이 크다. 기준 ±0.5%p를 아직 못 맞췄다.
  격차 체감 오차(`perceiveSd`)는 이 차이를 줄이지 못했다(+0.99).
- **추가합격**: 모형 밖 대학 원서가 전부 합격해도(q = 1.0) 전체 89.0%로 실제 92.5%에 조금 못 미친다.
  다군 추가합격은 실제의 절반이다. 실제 다군 합격자는 가·나군으로 많이 빠지는데,
  시뮬레이션은 원서 3장의 목표를 군에 무작위로 배정해서 이를 재현하지 못한다.
- 합격확률 곡선: σ(−1.15 + 2.02 × 격차), 50% 지점 +0.57%p. 70% 컷 차이만큼 위치를 믿기 어렵다.

## 반영하지 않는 것

수능 최저, 학생부, 전형별 세부 규칙, 모형 밖 대학과의 실제 경쟁, 실제 성적표-대응표 불일치,
연도 간 경쟁률 변동의 원인(모집인원 변경·전년도 입결에 따른 회피 등).
2026학년도 한 해의 경쟁률로 학습했으므로 다음 해 예측으로 쓰면 그만큼 오차가 커진다.
