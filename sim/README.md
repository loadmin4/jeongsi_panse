# 모의 지원 시뮬레이터 — 합격확률 곡선 학습

앱의 합격확률은 격차(%p)를 임의로 고른 로지스틱 곡선 `σ(격차)`에 넣은 **참고 수치**다.
이 도구는 가상 수험생 30만 명이 앱과 같은 엔진으로 격차를 보고 가·나·다군에 지원하는 상황을 만들고,
실제 모집인원으로 합격·추가합격을 돌린 뒤 **"격차가 이만큼일 때 실제로 몇 %가 합격했나"를 학습**한다.

**앱은 건드리지 않는다.** 결과는 `sim/out/`에 리포트로만 남는다.

```bash
npm run sim                              # 30만 명 × 1회 (약 40초)
node sim/run.js --runs 3                 # 시드를 바꿔 3회 → 학습값의 흔들림(±) 확인
node sim/run.js --students 100000 --cut avg --seed 1
```

→ `sim/out/report.md` (사람용), `sim/out/report.json` (수치)

## 흐름

| 단계 | 내용 | 코드 |
|---|---|---|
| 1. 성적표 | 공통 능력으로 상관된 국·수·탐 백분위(정의상 균등), 영어 등급, 인문/자연 | `makePopulation` |
| 2. 격차 | 1,535개 학과마다 앱 엔진(`src/engine.js`)으로 환산총점·합격선·격차 계산. 수험생별 대응표 보정까지 동일 | `scoreStudent`, `cutTotalFor` |
| 3. 지원 | 원서 3장에 목표 격차(안정 +1.5 · 적정 +0.3 · 상향 −1.2 + 개인 성향)를 군별로 배정해 가까운 학과를 고름 | `chooseApplications` |
| 4. 선발 | 학과는 환산총점 순으로 모집인원만큼, 학생은 합격한 곳 중 합격선이 가장 높은 곳에 등록. 학생 제안 지연수락 = 추가합격이 끝까지 돈 상태 | `deferredAcceptance` |
| 5. 학습 | 원서마다 (지원 시점 격차, 최종 합격선 이상이었나)로 `P = σ(a + b·격차)` 적합 | `fitLogistic` |

## 결과를 읽는 법

리포트의 **현실성 점검(shift)**을 먼저 본다.

- shift = 시뮬레이션 등록자 70% 컷 − 「어디가」 실측 합격선 (환산총점 %p, 격차와 같은 단위)
- 0에 가까워야 시뮬레이션의 경쟁 수준이 현실과 같다. +면 실제보다 치열해서 학습 곡선이 그만큼 오른쪽으로 밀린다.
- **|shift| > 0.5%p이면 학습 곡선의 위치(50% 격차)를 믿지 않는다.** 기울기는 상대적으로 덜 민감하다.

## 현재 결과 (기본 가정, 30만 명 × 3회)

| | 학습 곡선 | 현재 앱 |
|---|---|---|
| 식 | σ(−4.01 + 1.99 × 격차) | σ(격차) |
| 합격확률 50% 격차 | +2.02%p | 0 |
| log loss | 0.165 | 0.575 |

**그러나 shift 중앙값이 +1.83%p다.** 기본 지원 행동 가정으로는 경쟁이 현실보다 치열하게 나오므로
위치(+2.02%p)는 가정의 산물로 봐야 한다. 경쟁률 중앙값은 비슷한데(5.75 vs 실측 5.47) shift가 큰 것은,
가상 수험생이 모두 합격선 근처를 노리고 점수가 정확해서 지원자 구성이 실제보다 촘촘하기 때문으로 보인다.
실제로는 지원자가 더 넓게 퍼져 있고, 대학의 실제 순위가 앱 계산과 완전히 같지도 않다.

**다음 단계**: 지원 행동 파라미터(목표 격차·선택 폭·점수 잡음)를 shift ≈ 0, 경쟁률 ≈ 실측이 되도록 보정한 뒤
그 상태에서 곡선을 다시 학습한다. 그 전에는 결과를 앱에 넣지 않는다.

## 반영하지 않는 것

수능 최저, 학생부, 전형별 세부 규칙, 모형 밖 대학(데이터에 없는 대학)과의 경쟁,
실제 수험생의 성적표-대응표 불일치(가상 성적표는 대응 곡선으로 만듦).
